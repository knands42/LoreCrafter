# LoreCrafter Project Structure

## Root Level Organization

```
├── app/                    # Application layer (HTTP handlers, middleware, routing)
├── internal/               # Private application code (not importable by other projects)
├── pkg/                    # Public packages (can be imported by other projects)
├── tests/                  # Test files and test utilities
├── scripts/                # Build and deployment scripts
├── examples/               # Code examples and demos
```

## Application Layer (`app/`)

- `app/api/` - HTTP server, routing, and API documentation
- `app/api/middleware/` - HTTP middleware (auth, error handling, CORS)
- `app/api/routes/` - Route handlers organized by domain
- `app/api/docs/` - Auto-generated Swagger documentation

## Internal Architecture (`internal/`)

### Core Layers
- `internal/domain/` - Business entities and domain models
- `internal/usecases/` - Business logic and application services
- `internal/interfaces/` - Interface definitions for dependency inversion
- `internal/config/` - Configuration management and environment setup

### Adapters (`internal/adapter/`)
- `internal/adapter/database/` - Database connections, migrations, queries
- `internal/adapter/email/` - Email service integration and templates
- `internal/adapter/security/` - Authentication and password handling
- `internal/adapter/llms/` - AI/LLM service integrations
- `internal/adapter/worker/` - Background job processing

### Supporting Code
- `internal/utils/` - Shared utility functions and helpers
- `internal/prompts/` - AI prompt templates organized by game system

## Generated Code (`pkg/`)

- `pkg/sqlc/generated/` - Type-safe database query code generated by SQLC

## Database Organization

### Migrations (`internal/adapter/database/migrations/`)
- Sequential numbered migrations (e.g., `000001_create-users-table.up.sql`)
- Separate up/down files for each migration
- `migrate.go` for programmatic migration execution

### Queries (`internal/adapter/database/queries/`)
- SQL files organized by domain (users.sql, campaigns.sql, etc.)
- Used by SQLC to generate type-safe Go code

## Testing Structure (`tests/`)

- `tests/integration/` - End-to-end API tests
- `tests/integration/setup.go` - Test environment configuration
- `tests/integration/test_utils.go` - Shared test utilities

## Naming Conventions

### Files and Directories
- Use snake_case for SQL files and database-related naming
- Use kebab-case for migration files
- Use camelCase for Go files following standard Go conventions

### Go Code Structure
- Domain models in `internal/domain/` with validation methods
- Use cases follow the pattern: `New{Domain}UseCase()`
- Handlers follow the pattern: `{Domain}Handler` with `Register{Domain}Routes()`
- Interfaces define contracts in `internal/interfaces/`

### Database Conventions
- Table names are plural (users, campaigns, campaign_members)
- Foreign key columns follow pattern: `{table}_id`
- Timestamps: `created_at`, `updated_at`
- Use UUIDs for primary keys

## Configuration Management

- Environment variables defined in `.env` (with `.env.example` template)
- Configuration struct in `internal/config/config.go`
- Viper for loading from files and environment variables
- Separate database URLs for development and testing
